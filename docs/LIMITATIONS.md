# Supported scope and explicit limitations

Static analysis intentionally does not execute source or pytest collection. Supported rules include sync/async functions, direct import aliases, nested lexical attribution, literal/dotted mock targets, matching resource contexts, direct module-object mutations, common timing/network/order/precision indicators and local branch complexity. Paired/metamorphic tests exercise aliasing, wrapping, shadowing and relevant/unrelated mocks.

Supported fixture scope: local and ancestor `conftest.py` definitions; direct class fixtures; bare/aliased `pytest.fixture` and `pytest_asyncio.fixture`; `name`, literal `scope`, `autouse`, direct dependencies, function `usefixtures`, direct parametrization and overriding a fixture while requesting its predecessor. Cycles, unresolved fixtures and dynamic scope produce diagnostics. Mutable literal/factory returns and yields are detected; `yield` alone is neither a risk nor a guarantee of cleanup.

Unsupported or incomplete cases:

- Dynamic decorators/imports, star imports, descriptor-based calls, arbitrary higher-order aliases, inheritance-driven test/fixture collection, class/module `pytestmark`, plugin-created fixtures and `request.getfixturevalue`. Function/class discovery is a static approximation, not runtime coverage.
- Cross-module helper call graphs, monkeypatching propagated through fixtures, arbitrary object methods such as a dynamically created HTTP client, `pytest-mock` plugin semantics, exception-sensitive mock/resource lifetime, and returned local variables whose mutability needs data-flow analysis. Unattributed local helper findings are retained as inconclusive. Known unresolved fixture requests remain visible.
- Conditional rebindings and closures need fuller control-flow/data-flow analysis. Builtin/module shadowing is handled for direct function parameters/assignments, but all possible dynamic Python bindings cannot be resolved. A documented unsupported construct must not be interpreted as proof of stability.
- `asyncio.gather`/`create_task` is an advisory concurrency signal, not proof of a race. Float equality is a precision smell and may fail deterministically. Dictionary iteration is ordered in supported Python versions; the legacy `ast_dict_iteration` name now represents known-set iteration. `ast_float_comparison` is a reserved compatibility dimension, not an `assertAlmostEqual` false-positive detector.
- Plain-text log parsing preserves full node IDs and explicit statuses but does not reconstruct authoritative phase outcomes, durations or run boundaries from arbitrary log formats. Use the pytest phase ledger for labels. Unattributed log evidence stays visible.
- Fingerprints include Python/config/lock files and installed distributions, collection order and known seed options; external service state, non-Python resources, arbitrary environment variables and hidden random sources require an explicit `--flaky-trail-env` identifier. Do not combine runs whose external state is uncontrolled. Worker IDs and attempts are stored, but worker scheduling is not claimed deterministic.
- Empty-reason XFAIL/XPASS and the standard strict-XPASS report prefix are normalized separately from ordinary failure. Custom plugins with nonstandard outcome formats may still require adapters. Collection failures are session failures, not fabricated per-test outcomes. Interrupted attempts remain incomplete; kill-before-setup has no per-test phase record. Retry traceback behavior is regression-tested with rewritten reports; execution with the real retry plugin is a separate integration gate.
- `SharedStateTrap` is an explicit shallow mapping proxy. Nested mutations are not intercepted; it is not automatically injected into fixtures.
- API response deadlines cannot kill CPU work in a thread. For hostile multitenant deployment, use a reverse proxy with request limits and a separately isolated worker process; this package does not claim hard process isolation.
- RAG embedding quality, live model responses, remote GitHub connectivity and real-world classification accuracy require separate evaluation. Unit/fake-adapter tests do not establish those properties. Atomic index switching preserves the previous collection; interrupted new collections may remain orphaned until explicit maintenance.
- Deployment images and GitHub Actions are declared in source. Current execution status belongs in an archive-bound verification report beside the final ZIP. `docs/history/0.2.0/` is historical. Source-level test success does not establish installed-wheel, browser, Docker or remote-CI success.

## 0.2.1 candidate boundaries

- A full log nodeid is required to attribute evidence to a static test candidate. Parametrized executions map to their static definition for source review only; this is not execution-label merging. Foreign or bare-name logs remain unattributed.
- Mock mitigation models direct module bindings and literal supported targets. Path-derived module names can differ from pytest import modes/package loading; local from-import timing, replacement behavior and dynamic rebinding remain conservative limitations. A matched patch is not proof that all effects are mocked.
- Static discovery approximates default pytest naming. Constructor exclusions and fixture-decorated test names are handled, but inheritance/custom hooks/collection modes remain outside full parity. Counts are explicitly static candidates, not collected test instances.
- Target-level normalized-AST clone checks may conservatively reject structurally similar tests. They are not a complete semantic clone detector for transitive fixtures/helpers or every alternative implementation.
- Context fingerprints are versioned and hash settings rather than storing arbitrary raw options. They do not capture all external state. Legacy rows without the new provenance cannot be upgraded by inference.
- The workspace exposes real static counts. Repository history, causal diagnosis, real-world recall/precision and calibrated probability are not fabricated when their data/providers are absent.
