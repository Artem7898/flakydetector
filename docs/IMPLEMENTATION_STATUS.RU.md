# Кандидат 0.2.1rc1: реализация и границы проверки

Основание: предоставленный исходный ZIP 0.2.0 и воспроизведения его аудита. Номера F01–F12 относятся к этому аудиту. Это не объявление production-ready и не публикация версии в PyPI/GitHub.

| Область | Реализовано | Что ещё требует допуска |
|---|---|---|
| F01 | Раздельный учёт origin и lookup namespace, парные mock-регрессии | Полная динамическая семантика Python и нестандартные import modes не заявлены |
| F02 | Удалён fallback всех логов к единственному тесту; unmatched evidence отдельно | Дополнительные форматы логов требуют отдельных адаптеров |
| F03 | Эффективные pytest options/ini, overrides, plugins, order в снимке; provenance v3; безопасная миграция ledger | Внешнее состояние сервисов/данных/seed всё ещё нужно контролировать явно |
| F04 | Clone guard на AST выбранного теста, а не всего модуля | Независимый reviewed corpus и проверка близких семантических клонов |
| F06/F12 | XFAIL/XPASS без причины, фазы, strict XPASS, traceback при outcome=rerun | Реальный pytest-rerunfailures и xdist должны пройти интеграционный прогон с установленными зависимостями |
| F05/F11 | LICENSE; allowlist; SHA-256 manifest; smoke wheel/container от final ZIP; история старых отчётов | Сборка wheel, locked install, Docker smoke и quality gates в подходящем окружении |
| F07/F08 | Кандидаты отдельно от групп; selected/parsed/rejected; уникальные места vs связи | Действительный collection manifest не подменяется AST-оценкой |
| F09/F10 | Snapshot/revision/request ID; cancellation; stale banners; nested validator; исходник находки; real-fixture SSR gate | Настоящий Vite build, React SSR и browser E2E после установки npm dependencies |
| Benchmark/ML | Обновлена semantic schema 2.1.0; старые модели/недостоверные labels не принимаются | Нет предоставленного независимого reviewed датасета: accuracy, calibration и новая production-модель не измерены |

## Проверки и отчётность

Фактические результаты находятся в сопровождающем отчёте проверки, связанном SHA-256 с финальным архивом. Встроенный документ не записывает ожидаемые результаты как выполненные. `docs/history/0.2.0/` содержит только старую историю.

В среде подготовки доступны Python 3.13 и предустановленные библиотеки. Source-import harness не равнозначен установке wheel или воспроизведению uv.lock. Недоступные Docker/npm dependencies/ruff/pyright не считаются успешными проверками. Node-тесты reducer/validator не выдаются за браузерный E2E.

## Дальнейший допуск

Запустите команды README в изолированном окружении. Сначала устраните реальные ошибки ruff/format/pyright, если они будут обнаружены; форматирование само по себе изменяет байты исходников. После любых изменений снова соберите ZIP и выполните `verify_release.py` именно для него.

Не объединяйте UI redesign с обещанием достоверного flake-rate: сейчас история исполнения не подключена к dashboard. Не назначайте старым наблюдениям provenance 3 вручную и не редактируйте manifest старой модели для обхода совместимости.
